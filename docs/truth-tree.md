# 矿难真相树（Truth Tree）

> **设计核心**：系统与作者**不保存**"矿难真相 = X"。
> 只保存一组**互相矛盾、各带可信度**的证据节点，由主角与读者自行拼合。
> 这正是"冷战 + 历史真相"主题转化为玩法（互动小说 / 世界模拟）的关键装置。

## 2. 证据关系（推理路径）

```
E4（工程师手记）─────┐
                     ├──▶ 指向"延迟抢救的存在"
E8（守夜人证词）─────┘
        │
        ▼
E5（密约残页）+ E6（沈祈的信）──▶ 指向"共谋"与"和谈被破坏"
        │
        ▼
E9（事故记录）──────────────▶ 指向"事故被利用"
        │
        ▼
E1 + E2 + E7（双方官史）────▶ 指向"嫁祸与洗脑"
        │
        ▼
        = 五层叠加的真相（L3）
```

## 3. 叙述者可信度分级（用于写作纪律）
- **高（可作推理骨干）**：史三工程师手记、E9 事故记录。
- **中（可用但需交叉验证）**：史一矿工口述、E5 密约残页、E8 军官证词、E10 批注。
- **低（多为歪曲）**：史二两盟官史、E1、E2、E7。
- **存疑（可能真可能伪）**：支线沈祈的多个版本日记、未被验证的复印件。

## 4. 玩法（若做互动小说 / 模拟器）
- 玩家每获得一个证据，更新"认知状态"，但**永远无法达到 100% 确定**。
- 不同证据组合 → 不同结论 → 影响可选项与结局。
- 详细规则见 `docs/design-systems.md`；数据见 `data/evidence.json`。
