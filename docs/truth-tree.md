# 矿难真相树（Truth Tree）

> **设计核心**：系统与作者**不保存**"矿难真相 = X"。
> 只保存一组**互相矛盾、各带可信度**的证据节点，由主角与读者自行拼合。
> **修订（据专家意见）**：读者体验收敛为**三层**；证据全部降为**支撑材料**；删除"幕后共谋集团/单一黑手"。

## 1. 读者的三层理解

| 层 | 读者理解 | 出现时机 | 支撑证据 |
|---|---|---|---|
| 第一层 | 矿难不像课本写的那么简单 | 卷一末～卷二 | E1/E2/E7 的矛盾、E3 |
| 第二层 | 当年有人**故意延迟救援** | 卷二～卷三 | E4、E8 |
| 第三层 | 可怕的不是某个人，而是一群人**为各自利益让意外变成战争** | 卷四 | E5、E6、E9、E10 交叉印证 |

> **纪律（信息不可靠，叙事可靠）**：读者可以不知道"谁先下令"，但**必须确信矿难发生过、有人延迟过救援**。

## 3. 推理路径（不指向单一凶手）

```
E4（手记）+ E8（证词）──▶ "延误救援"确实存在
        │
E5（密约）+ E6（译者信）─▶ 和谈本可能成功，却被既成事实破坏
        │
E9（事故记录）──────────▶ 事故被利用、被定性为"敌破坏"
        │
E1/E2/E7（双方官史）────▶ 双方各自嫁祸
        ▼
= 多方各自"看起来合理"的行为叠加（L3）
（没有单一黑手，没有统一策划的组织）
```

## 4. 叙述者可信度分级
- **高**：史三工程师手记、E9 事故记录。
- **中**：E3 矿工口述、E5 密约残页、E8 军官证词、E10 批注。
- **低**：史二两盟官史、E1、E2、E7。
- **存疑**：译者多版本遗物、未验证的复印件。

## 5. 玩法（若做互动小说 / 模拟器）
- 玩家每获得一个证据，更新"认知状态"，但**永远无法达到 100% 确定**。
- 不同证据组合 → 不同结论 → 不同可选项与结局。
