# AScombat 

> 一个关于**历史的迷雾、科技的伦理与两个阵营的年轻人**的叙事项目。
> A narrative project about the fog of history, the ethics of technology, and a generation caught between two alliances.

---

## 这是什么

AScombat 是一个**叙事项目**，不是（至少现在不是）一个游戏项目。

它的核心，是一套已经成形、且**主题闭环**的故事结构：

```
火之联盟 vs 水之联盟（冷战式长期对峙）
        ↓
中立国家 + 综合魔法大学
        ↓
主角进入大学，结识不同阵营的人
        ↓
调查二十年前的矿难，发现历史并非课本所写
        ↓
水火魔法合作 → 蒸汽机 → 水泵
        ↓
技术与历史同时揭开真相
        ↓
主角必须选择：技术与真相，公开到什么程度
```

**它真正的主题**不是"火魔法 vs 水魔法"，而是一句话：

> **人如何在一个被历史和政治塑造的世界里，重新认识"敌人"。**

两个副主题：
- 真相并不天然带来和平。
- 技术本身不能决定未来，使用技术的人才决定未来。

## 它不是什么

- 不是"魔法版美苏冷战"。现实原型只是作者的**素材库**，正文 **绝不 1:1 影射**任何现实国家（见 `docs/world.md`）。
- 不是无限的设定集。本项目**主动控制设定的横向膨胀**，并遵守"三层信息"原则。
- 不是"科技带来和平"的爽文。科技的走向由**使用它的人和制度**决定。

## 文档关系（重要）

- `settings.txt`：最初的原始设定，**只读，不改**。
- `世界设定扩展.md`：设定**素材库**，含现实原型与冷战影射，供创作参考。
- `docs/`：**唯一事实源（Single Source of Truth）**。与素材库冲突时，以 `docs/` 为准。
- `data/`：`docs/` 的机器可读版本，供后续游戏 / AI 使用。

## 设计原则

1. **三层信息**：读者理解只有三层（矿难不简单 → 有人故意延误救援 → 可怕的是"一群人让意外变成战争"）。六层细节只作支撑证据，不给读者看。
2. **信息不可靠，但叙事可靠**：史料可以骗人，作者不能；读者可以不知道"谁先下令"，但必须确信"矿难发生过"。
3. **没有幕后大反派**：灾难由多方"看起来合理"的行为叠加而成，反派是制度与惯性，不是某个人或某个组织。
4. **反 1:1 影射**：现实原型只保留"模式与心态"，任何现实国家都不能完整映射到某一盟。
5. **魔法 = 操纵，而非创造**：不存在凭空造水 / 凭空生能的魔法（详见 `docs/magic.md`）。
6. **人物优先、场景优先**：世界通过食堂、课堂、宿舍、实验室、矿井被读者"撞上"，而不是通过设定说明。
7. **科技是镜子**：同一项技术既能救人也能杀人，故事不替读者下结论。

## 路线图

- [x] v0.0 — 原始设定与扩展素材

## 如何使用

- **读者**：从 `docs/chapters.md` 看故事结构，从 `docs/world.md` 了解世界。
- **创作者**：以 `docs/` 为唯一事实源写作，从 `世界设定扩展.md` 取灵感。
- **开发者 / AI**：读取 `data/*.json`；规则见 `docs/design-systems.md`。
